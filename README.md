# 求职自动投递助手

BOSS直聘 / 前程无忧 / 应届生求职网 三平台的岗位采集 + AI 去坑评估 + 队列投递工具。

一个油猴脚本负责「抓岗位、点详情、投递」，一个跑在本机的 Python 服务负责「算真实到手薪资、判断值不值得去」。
大模型的 Key 只存在浏览器本地，服务端不落盘，脚本源码里也没有 Key。

```
浏览器（油猴脚本）
   │  抓列表 / 读详情 / 点投递
   ├──────────────► BOSS直聘 · 前程无忧 · 应届生
   │
   └──► POST 127.0.0.1:8899 ──► 本地评估服务（Python） ──► 任意 OpenAI 兼容大模型
                                 工时/月薪/时薪由代码算，模型只做判断
```

> **免责声明**：自动投递可能违反招聘平台的用户协议，存在账号被限制的风险。本项目默认是「确认队列」模式
> （逐条等你点确认），限速、每日上限、夜间静默默认开启。请自行评估风险，不要用它刷量。
> 仅用于个人求职，请遵守各平台规则与当地法律。

---

## 它解决什么问题

招聘信息里的「6-10K」通常不等于到手 6-10K。这个工具做的事，就是把每条岗位拆成三件事：

1. **名义薪资 → 现实月薪**：按描述里的工时、月休、提成结构算一遍，例如 `5-10K` 实际是 `2350-3200`；
2. **列出坑点**：`[硬伤]` 卡年龄 / 12 小时班制 / 社保不写；`[软坑]` 值班无加班费；`[待确认]` 社保基数、发薪日；
3. **给一个分数和结论**：`推荐 72分` / `观望 55分` / `别投 40分`，低于阈值的不会进投递队列。

数字**全部由 Python 代码计算**，模型只负责「这段描述值不值得去」。小模型算数不可靠（会把月工时算成 171 小时），
所以算术和判断是分开的。

## 功能

| 功能 | 说明 |
|---|---|
| 三平台列表抓取 | BOSS 读 Vue 实例数据（DOM 薪资是私用区乱码）；前程无忧读 `sensorsdata` JSON；应届生读组件 props |
| 自动搜索 | 按「关键词别名 × 优先城市」逐页翻，每翻一页就地评估（此时卡片还在 DOM 里，能读到正文） |
| AI 去坑评估 | 逐条请求、逐条显示，评一条出来一条，可随时「停止评估」 |
| 真实薪资拆解 | 工时、保底、月薪、时薪由本地代码算；模型输出会做引文校验，编造的内容会被删掉 |
| 投递队列 | 可跨页面继续（状态存 GM 存储），支持「确认队列」与「极速全自动」两种模式 |
| 多标签页并行 | 三个平台各开一个标签页同时扫描/评估/搜索互不干扰，投递只在一处发起 |
| 投递台账 | 已投记录、每日上限、夜间静默；同一岗位不会重复投 |
| 公司口碑 | 必应检索公开页面 + 模型总结（只依据摘要，搜不到就明说没有） |
| 多服务商 | DeepSeek / 智谱 / 百炼 / 硅基流动 / 混元 / 方舟 / Groq / Ollama / 自定义，面板里选预设填 Key |

## 快速开始

### 1. 环境

- Python 3.8+
- 依赖只有一个：`pip install requests`
- 浏览器 + [Tampermonkey](https://www.tampermonkey.net/) 或 [脚本猫](https://scriptcat.org/)

### 2. 启动本地评估服务

```bash
cd plugin
pip install -r requirements.txt
python job_eval_server.py --port 8899
```

看到 `评估服务已启动：http://127.0.0.1:8899` 即可，**窗口别关**。

端口要和脚本里的一致：脚本默认填的是 `http://127.0.0.1:8899`。
如果换端口（例如 `--port 9000`），要去面板「求职意向 → AI 评估服务地址」同步改。

> 服务默认监听 `127.0.0.1`，只有本机能访问。不要改成 `0.0.0.0` 暴露到局域网。

### 3. 安装脚本

Tampermonkey / 脚本猫 → 新建脚本 → 粘贴 `plugin/求职自动投递.user.js` 全文 → 保存。

> 油猴不会自动覆盖已安装的脚本。更新版本后需要重新粘贴一次（或从文件导入）。
> 脚本已声明 `@connect 127.0.0.1`，否则跨域请求本地服务会被拦。

### 4. 配置大模型（一次就好）

打开任一平台页面 → 点右下角悬浮球 → 「求职意向」：

1. 「服务商预设」选一个，地址和模型会自动填好；
2. 粘 API Key；
3. 点「测试连接」，显示 `连通 754ms · 模型 · 回复「可用」` 就对了。

| 预设 | 默认模型 | 备注 |
|---|---|---|
| 硅基流动 SiliconFlow | `XingChenAGI/Xing4.0-29B` | 免费，默认项 |
| 智谱 GLM-4-Flash | `glm-4-flash` | 免费 |
| 阿里云百炼 | `qwen-plus` | 新用户有免费额度 |
| DeepSeek 官方 | `deepseek-chat` | 按量计费，便宜 |
| 腾讯混元 lite | `hunyuan-lite` | 免费额度 |
| 火山方舟 Doubao | `ep-xxxxxxxx` | 模型处要填**推理接入点 ID**，不是模型名 |
| Groq | `llama-3.3-70b-versatile` | 免费，国内需代理 |
| 本地 Ollama | `qwen2.5:7b` | 离线可用，Key 随便填或留空 |
| 自定义 | — | 任何 OpenAI 兼容接口，地址填到 `/v1` 或 `/v3` |

Key 存在油猴 GM 存储里（浏览器本地），请求时随包发给 `127.0.0.1:8899`，由本机转发给服务商。
服务端不写盘、不落日志。共享电脑上用完请清空 Key。

也可以不用面板，直接在 `plugin/.env` 里放一把硅基流动的 Key 作为兜底：

```ini
SILICONFLOW_API_KEY=sk-xxxxxxxxxxxxxxxx
```

面板里没填 Key 时会用它。两者都有时以面板为准。

### 5. 开始用

1. 打开 **BOSS直聘 / 前程无忧 / 应届生求职网** 的搜索结果页；
2. 悬浮球 → 「求职意向」：填必含关键词、城市、最低分 → 保存；
3. 回「投递队列」：

- 打开列表页后**自动评估新岗位**（3 秒防抖，只评没评过的；可在设置里关）；
- 「自动搜索」：按关键词 × 城市逐页收集，翻一页评估一页；
- 「AI 评估本页（只评新的）」：手动补评；
- 每条显示 `推荐/观望/别投 + 分数 + 现实月薪 + 时薪 + 坑点`；
- 「立即投递这条」手动投，或勾选后「勾选加入队列 / 全部加入并开始」走自动队列。

## 关键词写法

支持同义词，用 `/`、`、`、`,`、`|` 分隔：

```
运维/技术支持   →  分别搜「运维」和「技术支持」
```

匹配和搜索用拆开后的词。早先版本把整串当一个关键词做子串匹配，结果一条都搜不到。

## 评估输出怎么读

```
观望 55分
现实月薪 5200-5400 · 时薪 26.3-27.3
保底5000+奖金浮动，到手约5200-5400；25岁以下卡死、奖金规则不明
[硬伤] 23-26年毕业，卡25岁以下
[硬伤] 提成占大头（5000底薪+奖金），奖金未写明比例
[待确认] 社保仅写五险一金，未写明缴纳基数和比例
```

- `推荐`：≥70 分且没有硬伤
- `观望`：分数够但信息不足或有软坑
- `别投`：有硬伤或分数过低

坑点分级：

| 级别 | 含义 | 例子 |
|---|---|---|
| `[硬伤]` | 原文明确写出的严重问题 | 12 小时班制、月末发薪、卡 25 岁、月工时超 250 |
| `[软坑]` | 能忍但要知道 | 经验要求偏高、值班可能没加班费 |
| `[待确认]` | 原文没写的信息 | 社保、公积金、发薪日、上下班时间 |

自动投递会跳过 `score < 最低分` 以及判为「别投」的岗位。

## 数字是怎么算的

全部在 `job_eval_server.py` 的 `local_math()` 里，与 `job_scan.py` 的口径一致：

- **工时**：从描述里抠上下班时间 + 月休天数，**扣掉午休**，得到月总工时；
- **底薪未披露 + 靠提成**：按当地最低工资量级估保底，不把提成当固定收入；
- **纯固定月薪**（8-12K 且不提提成）：按下限九折估，再扣社保个人部分；
- **时薪** = 现实月薪 ÷ 月总工时；
- 模型给的 `real_monthly` / `hourly` 若与本地算出的数字冲突，以本地计算结果为准。

模型输出还会做**引文校验**：模型说的每个坑点必须能在原文里对上，对不上的会被标记或删掉，
避免出现「单人岗」「不包吃住」这种原文根本没写的内容。

## 接口

服务只有三个接口，方便自己接别的前端。

```http
GET /health
→ {"ok": true, "models": ["XingChenAGI/Xing4.0-29B", "..."], "envKey": true, "cached": 0}
```

```http
POST /evaluate
{
  "jobs": [{
    "jobId": "xxx", "platform": "boss",
    "title": "运维工程师", "company": "某某科技",
    "salary": "6-10K", "city": "重庆", "tags": ["双休"],
    "desc": "岗位职责正文…", "url": "https://..."
  }],
  "llm": {                       // 可选，不传则用 .env 的 Key
    "baseUrl": "https://api.siliconflow.cn/v1",
    "apiKey": "sk-...",
    "model": "XingChenAGI/Xing4.0-29B",
    "noThinking": true
  }
}
→ {"ok": true, "results": [{
    "jobId": "xxx", "score": 55, "verdict": "watch",
    "real_monthly": "5200-5400", "hourly": "26.3-27.3",
    "flags": [{"level": "hard", "text": "卡25岁以下"}],
    "reason": "…"
  }]}
```

```http
POST /company
{"company": "某某科技", "summarize": true}
→ {"ok": true, "count": 6, "results": [{"title": "…", "url": "…", "snippet": "…"}], "summary": "…"}
```

`verdict` 取 `pass` / `watch` / `reject`；`level` 取 `hard` / `soft` / `unknown`。

## 多标签页

三个平台各开一个标签页同时跑是支持的，处理方式：

- 自动搜索进度按平台分键（`jaap_search_v1:boss` 等），互不覆盖；
- 待投队列是三平台共用的，但**按平台分层显示**，各页只投自己的岗位；
- 投递队列有「主权」判断：队列在 BOSS 页跑，51job 页只读，不会去 pause 或抢占；
- 同一把 Key 的评估请求在服务端串行排队，避免免费额度被并发打成 429。

## 数据存在哪

| 键 | 内容 |
|---|---|
| `jaap_settings_v1` | 求职意向、服务商、Key、阈值 |
| `jaap_records_v1` | 投递台账（已投岗位） |
| `jaap_staging_v1` | 待投队列（三平台共用） |
| `jaap_runner_v1` | 投递状态机（跨页面恢复） |
| `jaap_search_v1:<platform>` | 自动搜索进度 |
| `sessionStorage: jaap_ai_cache / jaap_desc_cache` | 当前标签页的评估结果与详情正文缓存 |

想彻底重来：面板里清空队列/台账，或直接删掉这些 GM 键。

## 已知限制

- **BOSS 的正文只在右侧详情面板里**：评估前要逐条点开卡片读一次，约 1 秒/条。读过的会缓存，重扫不再读。
- **前程无忧 / 应届生的列表卡片没有正文**：只能基于标题、薪资、标签评估，更容易被判「信息不足」。
- **站点会改版**：选择器失效时板块会显示「未识别到职位卡片」，需要按页面实际结构调整脚本顶部 `SEL*` 配置区。
- **免费模型判断力有限**：`reason` 偶尔跑偏，但数字是准的。介意就换 DeepSeek / Qwen-Plus。
- **公司口碑只能搜到公开可抓的内容**：百度、搜狗、DuckDuckGo 会被拦；知乎、看准网、职友集有反爬。
  所以经常只能给出官网/百科信息，模型会如实说「缺少可信的员工评价」，不会编造。
- **自动投递有账号风险**，见文首免责声明。

## 常见问题

**评估一直转圈 / 提示连接失败？**
先确认 `http://127.0.0.1:8899/health` 能打开。打不开说明服务没起或端口不对。

**提示 `401` 或 `Invalid token`？**
Key 错了或没余额。面板里点「测试连接」会直接报出来。

**面板显示「未识别到职位卡片」？**
页面还没加载完、当前不是搜索结果页，或站点改版。先点「重新扫描本页」，仍为 0 就要改 `SEL` 配置。

**评估要多久？**
免费模型约 5-6 秒/条，纯 CPU 的 Ollama 更慢。一批 15 条大约 90 秒，评一条显示一条。

**会不会重复投同一家？**
不会。投递前会查台账（`jaap_records_v1`），已投的跳过。
